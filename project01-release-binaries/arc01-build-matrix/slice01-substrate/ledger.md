## What Worked

- Manually walking each build stage interactively (parser, then grounder's
  cpddl third-party deps, then bliss, then libpddl.a, then grounder `src/`,
  then engine) *before* writing its script caught every compiler-override
  trap (env vars honor cpddl's `?=` defaults but not the grounder `src/`
  Makefile's plain `=` Darwin default; command-line `make` vars are
  required there) without burning script-edit/re-run cycles on trial and
  error.
- Extracting bliss into a scratchpad copy first, diffing by hand, and
  dry-running the resulting patch against a *fresh* re-extraction before
  ever touching the real build caught a subtlety (the memleak patch must
  apply first, since it touches a different file) that would otherwise
  have surfaced as a confusing mid-build patch-application failure.
- Testing the smoke harness's own failure mode (F-8's "tamper one
  expectation") immediately surfaced the ANSI-stripping bug rather than
  leaving it to whoever next hit a real parser color-output edge case.
- Running `patch --dry-run` (or `git apply --check`) before every real
  application, both for the bliss patch and inside `fetch-upstream.sh`'s
  mismatch test, made every failure mode a controlled, deliberate
  observation rather than a mid-build surprise.
